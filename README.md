# A-Track Nature Information Pathways demo

> **Read [IMPORTANT_READ_FIRST.md](LIMITATIONS_AND_CAVEATS.md) as well as the LICENSE documents before setting up or running anything.**
> These scripts are for demonstration only, tailored to one site and case, and use  maps created with an experimental method.
> Read [DATA_REFERENCES.md](DATA_REFERENCES.md) for third-party data sources.
> **The demo lookup table is site-specific and must not be reused for another location.**

This repository contains scripts, input data and instructions to recreate the worked example featured in *Decision-Ready Nature Information - A guide to applying ecosystem accounting principles in business* and the more detailed technical version of this example in *'Case 1: Tracking impacts on stocks at priority locations'* of the *Nature Information Pathways Framework - Top-down demonstration*. These are outputs of the EU Horizon project A-Track.

This repository provides materials to gain hands-on experience generating business-relevant ecosystem extent and condition metrics following a Nature Information Pathway (NIP). 

It covers Nature Information Pathway steps **1.3 (treatments to organise data - ecosystem
extent)** and **1.4 (application-focused transformation of data)**. Opening and closing EUNIS habitat maps
(2021 and 2024) become extent tables, plots, conversion tables, connectivity metrics and productivity statistics.

## Getting started

1. Read the important information and data references linked above.
2. [Set up Python and the repository](#repository-and-python-setup), using [PyCharm or VS Code](#pycharm-or-vs-code)

## Repository and Python setup

Use a separate Python environment so the demo's dependencies do not affect other projects.
For a new installation, Python **3.11 or 3.12** is a suggested starting point for geospatial package availability,
not a guarantee of a tested version range. Dependencies are listed in
[`requirements.txt`](NIP_top_down_demo/requirements.txt);
versions are not currently pinned.

Install [Python](https://www.python.org/downloads/) and [Git](https://git-scm.com/downloads) if needed.
You can also use GitHub's **Code > Download ZIP**, extract it, and open the extracted repository instead of cloning.
No account or additional data download is needed for the first four analysis scripts.

The following commands are for **Windows PowerShell**, starting in the folder where you want the repository:

```powershell
git clone https://github.com/VITObelgium/A-Track_NIP.git
cd .\A-Track_NIP
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r .\NIP_top_down_demo\requirements.txt
cd .\NIP_top_down_demo
```

If `python` is not recognised, use the Windows Python launcher (`py`) to create the environment.
If PowerShell blocks activation, you do not need to change your system's execution policy: run
`.\.venv\Scripts\python.exe -m pip install -r .\NIP_top_down_demo\requirements.txt` from the repository root,
then use `..\.venv\Scripts\python.exe` instead of `python` in the demo commands below.
For other operating systems, follow the official [venv creation and activation instructions](https://docs.python.org/3/library/venv.html)
and use that system's path separators.

If geospatial dependencies fail to install with pip, an alternative is a fresh
[Miniforge/conda environment](https://conda-forge.org/docs/user/introduction/) using conda-forge packages.
From the repository root:

```powershell
conda create -n a-track -c conda-forge python=3.12 numpy pandas geopandas rasterio shapely scipy scikit-image networkx matplotlib pip
conda activate a-track
python -m pip install -r .\NIP_top_down_demo\requirements.txt
cd .\NIP_top_down_demo
```

Choose either the virtual environment or conda route, not both in the same environment.
Keep the selected environment active whenever you open a new terminal to run the demo.

## PyCharm or VS Code

### PyCharm

1. Open the cloned/extracted **`A-Track_NIP` repository folder** as a project.
2. In the project's Python interpreter settings, select the environment created above
   (`A-Track_NIP\.venv\Scripts\python.exe` on Windows), or create a new virtual environment in PyCharm.
   See [configure a virtual environment](https://www.jetbrains.com/help/pycharm/creating-virtual-environment.html).
   Install `NIP_top_down_demo\requirements.txt` into that interpreter if you have not done so already.
3. Read the important information, then open [`EA_setup.py`](NIP_top_down_demo/EA_setup.py) and check the configuration below.
4. Under **Run > Edit Configurations**, add a **Python** configuration. Select **Module name**, not Script path,
   and enter `Metrics_scripts.Ecosystem_extent` (without `.py`). Set **Working directory** to the full path of
   your `A-Track_NIP\NIP_top_down_demo` folder and use the selected project interpreter.
   See [Python run/debug configurations](https://www.jetbrains.com/help/pycharm/run-debug-configuration-python.html).
5. Before analysis, use module name `Check_setup` with the same interpreter and working directory to check setup.
   Then run the extent configuration. Duplicate it for the other modules in the run-order table, changing the module name.
   Alternatively, use the terminal commands below with the same interpreter and working directory.

**Why module mode?** The scripts live in `Metrics_scripts`, but `EA_setup.py` and `EA_utils.py` live one folder above.
Running `python -m Metrics_scripts.Ecosystem_extent` from `NIP_top_down_demo` makes both available.
Running `python Metrics_scripts\Ecosystem_extent.py` directly, or running from inside `Metrics_scripts`,
can fail with `ModuleNotFoundError: No module named 'EA_setup'`. Do not move or duplicate the helper files.

### Run in full or explore block by block

For the simplest, reproducible demo, run each module in full. The scripts also contain `# %%` blocks for interactive
exploration. In an IDE with cell support, or by sending selected code to a Python console, run imports first and
then every block in order in the **same session**. Use `NIP_top_down_demo` as the console's working directory
and ensure it is on the Python import path. Cell execution support depends on your IDE/version.
After editing `EA_setup.py`, **restart the console/kernel and rerun from the imports**; Python otherwise caches
the imported settings.

## Configure `EA_setup.py`

**This is the file to edit before running the demo.** It is configuration, not an analysis script to run first.
Leave `EA_utils.py` and the metric scripts unchanged for the bundled example.

Check `base_dir`, `inputs`, input-file paths and `output_dir` for your computer. By default,
`base_dir = Path(__file__).resolve().parent` finds this demo folder automatically, so a fresh clone already points
to the bundled data. **You do not need to replace it with a personal absolute path.**
If your inputs or outputs are elsewhere, set those paths explicitly, for example
`inputs = Path(r"C:\my_data\Demo_input_data")` or `output_dir = Path(r"C:\my_results\A-Track")`.
Keep the corresponding subfolder structure, or adjust each individual input path.

| Settings | What to check or optionally adjust |
|---|---|
| `site_polygon_path`, `raster_opening_path`, `raster_closing_path` | Site boundary and opening/closing habitat maps. Keep the bundled files for the document demo. |
| `lut_path`, `threat_csv`, `legend_qml_path` | Lookup tables, their column/separator settings and the map colour legend. |
| `buffer_size_m`, `year_labels` | Extent analysis buffer (default 0 m) and labels (2021, 2024). |
| `priority_level2`, `priority_level3`, `natural_groups`, `other_groups` | Priority habitats and summary groups. Defaults are tailored to this case. |
| `habitat_codes`, `MIN_AREA_HA`, `DISPERSAL_THRESHOLDS`, `LANDSCAPE_RADIUS_M` | Connectivity habitat, patch size, dispersal distances and landscape radius. |
| `tprod_dir`, `productivity_codes`, `productivity_buffer_m`, `ref_*` | Productivity tiles, habitat, buffer and reference-site inputs. |
| `output_dir` and per-script output folders | Where generated results will be saved. Change these before running if results belong elsewhere. |

## *NB*

The supplied habitat maps cover only a **500 m site buffer**. The source document for the demonstration *'Case 1: Tracking impacts on stocks at priority locations'* of the *Nature Information Pathways Framework - Top-down demonstration* uses a 10 km connectivity landscape and
a 50 km productivity landscape; this small demo therefore does **not** reproduce those landscape results exactly.
Larger buffer settings require larger input habitat rasters. The settings belong in `EA_setup.py`, not in the scripts.
For a different site, read the caveats again and build a location-appropriate LUT from the original sources.

## Check your setup

After checking `EA_setup.py`, run this from `A-Track_NIP\NIP_top_down_demo` using your selected environment:

```powershell
python -m Check_setup
```

The check prints the Python interpreter, attempts to import every dependency in `requirements.txt` (including `hda`),
checks that the configured input files can be opened, and probes write access to each output folder or its nearest
existing parent. It does not create output folders, run analyses, download data or read/display credentials.
Failures include corrective instructions and return exit code **1**; a successful check returns **0**.
Warnings identify optional or skipped checks, not failures.

Missing TPROD tiles are expected in a fresh clone and do not fail the basic check. After downloading them,
check productivity prerequisites too:

```powershell
python -m Check_setup --productivity
```

This additionally requires a closing site raster and readable TPROD tile files for each configured year.
Reference-site inputs are checked when enabled; set both reference rasters to `None` to disable that comparison.
The check confirms file availability, **not** valid raster contents, spatial coverage, complete tile coverage,
all analysis settings or WEkEO authentication. The analysis scripts still perform their own data checks.
Rerun the preflight check after changing environments or input/output paths.

## Run the demo in document order

**Run these commands from `A-Track_NIP\NIP_top_down_demo`, with your selected Python environment active.**
Use module names exactly as shown; do not append `.py`.

| Order / document step | Command | What it produces or needs |
|---|---|---|
| 1 / 1.3: ecosystem extent | `python -m Metrics_scripts.Ecosystem_extent` | Area tables at EUNIS levels 1-3 and clipped maps. Run first. |
| 2 / 1.4: ecosystem overviews | `python -m Metrics_scripts.Extent_transformations` | Natural/anthropogenic habitat and Red List summaries; needs step 1's tables. |
| 3 / 1.4: conversion | `python -m Metrics_scripts.Ecosystem_conversion` | Priority-habitat transitions between years; needs step 1's clipped rasters. |
| 4 / 1.4: connectivity | `python -m Metrics_scripts.Ecosystem_connectivity` | Patch and graph outputs, IIC, nearest-neighbour distance, effective mesh size and stepping-stone importance. Reads the original inputs independently. |
| 5a / 1.4: get productivity data | `python -m Metrics_scripts.Download_TPROD` | Downloads TPROD tiles; requires internet access and WEkEO credentials (below). |
| 5b / 1.4: grassland condition | `python -m Metrics_scripts.Grassland_productivity` | Productivity statistics for the site, site + buffer and reference site; requires the TPROD tiles. |

Steps 2-4 are not prerequisites for one another; this order follows the document's narrative.
If you change settings affecting extent outputs, rerun step 1 before steps 2 and 3.
If you set `raster_closing_path = None`, extent can run for the opening year alone, but conversion needs both years.

### Productivity download: one-off extra setup

Create a free [WEkEO account](https://www.wekeo.eu) and accept the relevant data-access terms.
The `hda` client is included in `requirements.txt`. Follow the
[HDA client configuration instructions](https://hda.readthedocs.io/en/latest/usage.html) to provide credentials:
use a `.hdarc` file **in your home folder, outside the repository**, containing:

```yaml
user: <your-WEkEO-username>
password: <your-WEkEO-password>
```

Alternatively, set `HDA_USER` and `HDA_PASSWORD` in your local environment or private IDE run configuration.
Never put credentials in Python scripts, tracked files or shared run configurations.
Run the downloader before productivity. It skips tiles already present in `tprod_dir`.
The demo uses tiles T30UWD and T30UWE for 2021 and 2024; the bounding-box search can also download neighbouring tiles.
Allow disk space for the raw downloads and derived rasters. Downloads go to `Demo_input_data\TPROD` by default,
which is ignored by Git.

### Optional graphical tools for exploring data

If you prefer a graphical interface to explore your site and available satellite or land-monitoring data:

- **[vresto](https://github.com/kalfasyan/vresto)** provides an interactive satellite-data browser for searching,
  viewing and downloading supported products. Follow its
  [installation and setup guide](https://kalfasyan.github.io/vresto/getting-started/setup/);
  use a separate environment to keep the A-Track demo dependencies unchanged.
- **[Copernicus Land Monitoring Service map viewer](https://land.copernicus.eu/en/map-viewer)** provides a
  browser-based graphical interface for exploring CLMS products, without installing a local application.

These are optional exploration tools, not required steps in the demo. The scripted TPROD download above remains
the recommended route for reproducing the productivity example. In particular, vresto's Dry Matter Productivity
overlay is a different product from the **10 m HR-VPP season-1 TPROD** tiles used here; it is not a substitute.

The filenames above assume the default 0 m extent buffer; buffer/radius settings appear in many output names.

Plots are saved to files rather than displayed in an interactive window.
Rerunning with the same settings writes to the same filenames; copy results or change the output directories
in `EA_setup.py` before comparing configurations.

## Troubleshooting and interpretation

| Symptom / question | What to check |
|---|---|
| `No module named 'EA_setup'` or `'EA_utils'` | Use module mode from `NIP_top_down_demo`, or the PyCharm module configuration above. |
| Missing third-party module | Confirm your IDE and terminal use the same interpreter; install `requirements.txt` with that interpreter's `python -m pip`. |
| Input file not found | Check `EA_setup.py` against the input-data table, including `Demo_site`, `Demo_lookup_tables` and `Reference_site`. |
| Missing extent CSV or clipped raster | Run `Metrics_scripts.Ecosystem_extent` first with the same buffer/settings. |
| Geometry extends beyond raster extent | Reduce the buffer/radius or provide larger habitat maps; the bundled site rasters cover only 500 m around the site. |
| Missing TPROD tiles or authentication failure | Check WEkEO credentials/data terms, run the downloader and confirm `tprod_dir`. |
| Changed settings have no effect in a console | Restart the console/kernel, then rerun the blocks in order. |

Level 1 classes without children (C, J, M) appear at several LUT levels but are counted once and retain their class
at all levels. Extent, transformations and conversion require level 3 site maps; connectivity and productivity
can also use coarser maps at the configured habitat level.

**Differences between two independently predicted maps are not verified ecosystem change.**
The conversion script is a pixel-by-pixel comparison for illustration, not a validated change-detection workflow.
Do not use demo outputs for real decisions, reporting or claims.
